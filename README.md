# YS Tag Usage

게임플레이 태그가 **어느 애셋의 어느 필드**, **어느 C++ 줄**, **어느 ini 설정**에서 쓰이는지 한 탭에서 보여주는 언리얼 에디터 플러그인.
태그 추가·삭제도 같은 탭에서 한다.

엔진 기본 기능(태그 매니저의 Search For References, `GetUnusedGameplayTags`)은 애셋 단위까지만 알려주고, 어느 필드인지와 C++ 참조는 모른다. 이 플러그인은 그 빈칸을 메운다.

## 요구 사항

- Unreal Engine 5.7 (다른 버전은 확인 안 됨)
- 에디터 전용. `GameplayTagsEditor` 플러그인을 쓴다 (엔진 기본 활성).

## 설치

```bash
cd <프로젝트>/Plugins
git clone https://github.com/jokate/YSTagUsage.git
```

프로젝트를 다시 빌드한다.

## 사용법

**툴 → YS → 태그 사용처**로 탭을 연다.

### 태그 트리 (왼쪽)

| 분류 | 기준 |
|---|---|
| 사용 중 | 애셋·C++·ini 중 어디서든 직접 쓰는 태그 |
| C++ 정의만 | C++ 로 정의했지만 하위까지 아무 데서도 안 쓰는 태그 |
| 미사용 | ini·데이터 테이블에만 있고 하위까지 아무 데서도 안 쓰는 태그 |

- 태그마다 `애셋 N` `C++ N` `ini N` 칩이 붙는다.
- 흐린 항목은 하위 태그만 해당하는 부모다.
- 태그는 입력 검색이 아니라 트리에서 클릭해 고른다.

### 사용처 (오른쪽)

- 요약: 태그 설명, 정의 위치, 애셋·C++·ini·상속 개수
- **애셋**: 애셋별로 묶은 필드 경로
  예) `GE_Recharge_Tick` › `컴포넌트[0] (…) › 진행 중인 태그 요구 사항.필수 태그`
- **C++ · ini**: `파일:줄` 과 그 줄의 코드
- 필터: 하위 태그 포함, 상속된 값 표시, 애셋 타입, 텍스트

### 더블클릭

- 애셋 행: 애셋 에디터를 열고 디테일 패널에서 해당 프로퍼티로 스크롤·강조한다. BP 는 클래스 디폴트를 띄운다.
- C++·ini 행: IDE 에서 해당 줄을 연다.

### 역방향

콘텐츠 브라우저에서 애셋 우클릭 → **이 애셋의 태그 사용처**. 그 애셋이 어느 필드에 어떤 태그를 세팅했는지 본다.

### 태그 추가·삭제

- **추가**: 왼쪽 위 `태그 추가`, 또는 트리 우클릭 → `하위 태그 추가…`
  - C++ 파일: 고른 `.cpp` 에 `UE_DEFINE_GAMEPLAY_TAG`, 같은 이름의 `.h` 에 `UE_DECLARE_GAMEPLAY_TAG_EXTERN` 을 한 줄씩 넣는다. 들여쓰기·BOM·줄바꿈은 원래 파일을 따른다. 빌드 전까지는 에디터 임시 태그로 보인다.
  - ini: 엔진 `AddNewGameplayTagToINI` 로 넣는다.
- **삭제**: 제목 옆 휴지통, 또는 트리 우클릭 → `태그 삭제…`
  - 고칠 파일과 남은 사용처 수를 보여주고 확인을 받는다.
  - C++ 정의·선언 줄을 지우고, ini 는 엔진 `DeleteTagFromINI` 로 지운다. 애셋 참조가 남은 ini 태그는 엔진이 거부한다.
  - 암시적 태그, 엔진·플러그인 C++ 태그, 데이터 테이블 태그는 지우지 않는다.

## 동작 방식

### 애셋 스캔

1. 태그를 저장한 애셋은 애셋 레지스트리에 태그 이름을 SearchableName 으로 남긴다 (`FGameplayTag` 직렬화). 이걸로 로드할 패키지를 추린다.
2. 후보를 백그라운드에서 나눠 비동기 로드하고, 프로퍼티를 재귀로 돌아 `FGameplayTag` / `FGameplayTagContainer` / `FGameplayTagQuery` 를 찾는다. 인스턴스드 서브오브젝트(GE 컴포넌트 등), 배열·셋·맵, `FInstancedStruct` 안까지 따라간다.
3. 결과는 `Saved/YSTagUsage/Cache.json` 에 패키지 저장 해시와 함께 남긴다. 다음 시작 때는 해시가 바뀐 패키지만 다시 본다.
4. 애셋을 저장·삭제·이름 변경하면 그 패키지만 갱신한다.

- 사람이 세팅하는 값만 센다: 편집 가능 필드(`EditAnywhere`/`EditDefaultsOnly` 등). `VisibleAnywhere`·`Transient`·`Deprecated` 는 뺀다.
- 같은 경로에서 아키타입(부모 CDO 등)과 같은 태그를 들고 있으면 **상속**으로 표시한다.

### C++ 스캔

프로젝트 `Source/` 의 `.h`·`.cpp` 를 텍스트로 훑는다.

- 정의: `UE_DEFINE_GAMEPLAY_TAG(_COMMENT|_STATIC)` 줄. 사용처로 세지 않는다.
- 사용처: `네임스페이스::태그변수`, `using namespace` 한 파일의 맨 변수 이름, 알려진 태그 이름 문자열 `"A.B"`

### ini 스캔

프로젝트 `Config/*.ini` 에서 태그 이름이 들어간 설정값을 찾는다. 태그 정의 섹션(`GameplayTagsSettings`, `GameplayTagsList`)은 뺀다.

## 한계

- 레벨(`.umap`)과 월드 파티션 외부 액터는 스캔하지 않는다. 레벨 배치 액터에 세팅한 태그는 안 나온다.
- BP 그래프 핀에 직접 넣은 태그 리터럴은 레지스트리 후보에 잡히지 않을 수 있다.
- C++ 스캔은 텍스트 기반이다. 문자열 조합·매크로로 만든 태그, `HasTag(부모)` 식 부모 매칭은 못 잡는다.
- C++·ini 스캔 범위는 프로젝트 `Source/`·`Config/` 뿐이다. 플러그인 소스는 보지 않는다.
- 디테일 패널에 바로 뜨지 않는 서브오브젝트(몽타주 노티파이 스테이트, SCS 컴포넌트 템플릿 등)는 더블클릭해도 애셋만 열린다.
- 생성기 스크립트가 만드는 파일에 넣거나 지운 태그는 스크립트를 다시 돌리면 덮인다. 파일 이름에 `Generated` 가 들어가면 생성기 파일로 보고 경고한다.
- 베타. 화면 동작(레이아웃, 포커스, 추가·삭제)은 충분히 검증되지 않았다.
